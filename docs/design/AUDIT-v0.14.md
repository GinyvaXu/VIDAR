# UI 审核 — VIDAR v0.14.0（基线）

审核对象：`work/design/audit-v014/` 下 12 张 1182×792 离屏截图（5 页 × 明暗 + 失败态）。
方法：ui-taste 评分表（`references/review-rubric.md`）+ impeccable 的 Operate 模式判据。
结论：**BLOCK（36/65）** —— 可用，但结构、状态表达与完成度不达标，支持全量重设计。

## 评分

| 维度 | 分 | 依据 |
|---|---:|---|
| 目的与第一印象（×2） | 4 | 一眼知道是 B 站转文档工具，主按钮可见 |
| 层级（×2） | 3 | 主操作可见，但输入区、进度区、日志区权重接近 |
| 布局与间距（×1） | 3 | 内边距统一，但内容无最大宽度、表格“内容”列大面积空置 |
| 字体（×1） | 3 | 字号成体系，但标题无 display 层级、数字非等宽 |
| 颜色（×1） | 3 | 单强调色克制，但语义色几乎未使用 |
| 深度与材质（×1） | 2 | 卡片全平，日志面板在浅色主题下是一块纯黑 |
| 动效（×1） | 1 | 无过渡、无状态变化反馈 |
| 无障碍（×2） | 2 | 焦点态不可见、11px 标签、状态仅靠文字 |
| 文案与错误（×1） | 3 | 主文案清楚，但步骤键名裸露、错误信息是内部术语 |
| 工艺与平台适配（×1） | 3 | 无快捷键、无菜单、弹窗遮挡上下文 |

加权总分：**36 / 65（< 41，BLOCK）**

## P0（必须修）

1. **错误弹窗遮挡上下文且无法行动**
   - 证据：`task-failed-dark.png`；`_on_failed` 只弹 `QMessageBox`。
   - 影响：用户看到原始 shape 报错，看不到失败步骤、不能从该步重跑。
   - 修复：错误内联到步骤行 + 右侧详情；弹窗只用于确认类操作。
2. **状态表达不完整**
   - 证据：失败行的“失败”为普通白字；进度条 0% 与“失败”并存；无耗时。
   - 影响：扫一眼分不清哪步失败、失败后能做什么。
   - 修复：状态 = 图标 + 颜色 + 文案；进度条进入错误态；补耗时与错误摘要。
3. **浅色主题里的黑色日志面板**
   - 证据：`task-light.png` 日志区纯黑，占页面 1/3。
   - 影响：破坏明暗一致性，且默认折叠更合理。
   - 修复：日志改为可折叠抽屉，浅色下用浅底等宽字。
4. **焦点不可见 / 小字不可读**
   - 证据：QSS 无 `:focus` 规则；版本号与辅助标签 11px。
   - 影响：键盘用户无法定位；低视力用户读不清。
   - 修复：统一 2px 焦点环；最小正文 13px、辅助 12px。
5. **空状态缺失**
   - 证据：队列表格、历史列表在无数据时是空白矩形。
   - 影响：首次使用不知道下一步做什么。
   - 修复：每个空状态给一句引导 + 一个主操作。

## P1（重要）

- 步骤表“步骤”列直接显示 `resolve/download/audio/asr/refine/ads` 英文键名。
- “从头开始”下拉语义不清；失败后重跑入口藏在其中。
- “打开输出目录/打开文稿/预览排版”放在输入卡片里，实际作用于上一条任务。
- 内容区无最大宽度，日志行宽超过 140 字符，阅读疲劳。
- 模型页只有表格；“已安装”是纯文字，无磁盘占用、无修复入口。
- 进度、耗时、ETA 信息缺失；批量运行时看不到单条进度。
- 侧栏“关于”是死页，v0.14 品牌表达仅剩 logo。

## P2（打磨）

- 圆角一律 14px，缺少 6/10/14 的层级。
- 表格表头对比度偏低（浅色下约 3:1）。
- 图标尺寸 16/18/20 混用，视觉重量不齐。
- 设置/主题切换按钮与导航项风格不统一。

## 有效之处（保留）

- 单强调色 + 中性底的做法是对的，不需要换成多彩。
- 明暗两套色板结构完整，有继续演进的基础。
- 表格化流水线让“卡在哪一步”有天然表达力。
- 文案整体克制、不营销腔。

## 未验证

- 200% 缩放、键盘全流程、读屏软件、高 DPI 多显示器。
- 真实长日志（数千行）下的滚动性能。
